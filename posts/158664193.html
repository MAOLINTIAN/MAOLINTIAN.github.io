我们来一次彻底的融合。我将以两个线程 A 和 B 并发执行一段代码为主线，串联起 JVM 运行时数据区域、类加载机制、JMM 内存模型、操作系统线程映射以及 CPU 调度。整个过程会按照时间顺序展开，你可以跟随线程的脚步，看到每个环节发生了什么。

我们有一个简单的类 Teacher，以及一个共享的锁对象 lock。两个线程 A 和 B 同时执行 createTeacher() 方法：

public class Test {

   
    private static final Object lock = new Object();  // 共享锁对象（在堆中）
    private int count;                                 // 共享变量（在堆中）

    public void createTeacher() {

   
        synchronized (lock) {

              // 线程A和B竞争这把锁
            Teacher t = new Teacher();  // 创建 Teacher 对象（局部引用，对象在堆中）
            count = count + 1;          // 对共享变量 count 进行非原子操作
        }
    }
}

假设 Teacher 类还未被加载过，线程 A 率先抢到了 CPU 时间片，开始执行。

第一阶段：类加载（由线程 A 触发）

1.1 线程 A 执行到 new Teacher()

  • 当JVM执行到 new Teacher() 时，发现 Teacher 类尚未加载，于是开始类加载过程，JVM 通过类加载机制开始加载。
  • 类加载过程（发生在线程 A 的上下文中）：
    1. 加载：通过类加载器（应用程序类加载器）找到 Teacher.class 文件，读入字节流，在堆中生成一个 java.lang.Class 对象作为入口，并将类的静态结构存入方法区（元空间）。
    2. 链接：
      • 验证：确保字节码安全。
      • 准备：在方法区中为静态变量分配内存并赋默认值（如 static int count 赋 0）。
      • 解析：将常量池中的符号引用替换为直接引用（比如把 Teacher 类的符号引用指向实际内存地址）。
    3. 初始化：执行 <clinit> 方法，为静态变量赋初始值，执行静态代码块。
  • 线程安全：JVM 保证类加载过程是同步的。如果此时线程 B 也试图加载 Teacher，它会发现类正在加载中，从而阻塞等待，直到线程 A 完成初始化。这保证了方法区中类的元数据唯一。

1.2 类加载完成后的内存布局

  • 方法区（元空间）：存放了 Teacher 类的类型信息（字段、方法字节码）、运行时常量池、静态变量（如静态字段的值或引用）以及 JIT 编译后的代码。
  • 堆：生成了一个代表 Teacher 类的 Class 对象（可通过 Teacher.class 访问）。
  • 此时，lock 对象早已在堆上（因为它是静态常量，在 Test 类加载时已创建）。

第二阶段：线程创建与操作系统映射

2.1 Java 线程的本质

  • 线程 A 和 B 可能是由线程池创建的，或者直接 new Thread()。无论哪种方式，JVM 都会调用操作系统内核的线程创建函数（如 Linux 的 clone 或 pthread_create）。
  • 每个 Java 线程对应一个内核线程，采用 1:1 模型。内核线程负责在 CPU 上真正执行。
  • 线程的创建涉及用户态 → 内核态切换：JVM 发起系统调用，内核创建线程控制块（TCB），分配内核栈，然后将新线程加入调度队列。

2.2 线程私有的 JVM 区域

每个 Java 线程在 JVM 内部拥有独立的：

  • 程序计数器（PC）：记录当前执行的字节码地址。这是线程切换后能继续执行的“书签”。
  • 虚拟机栈：存储栈帧（每个方法对应一个栈帧），包含局部变量表、操作数栈、动态链接、方法出口。
  • 本地方法栈：为 native 方法服务。
    这些区域在 JVM 初始化线程时分配，线程销毁时回收。

2.3 操作系统层面的线程上下文

  • 内核线程有自己的寄存器集合（包括通用寄存器、栈指针、指令指针等）、内核栈、调度优先级等。
  • 上下文切换发生时，操作系统会保存当前线程的寄存器状态到内存（内核空间），然后加载另一个线程的状态。

第三阶段：线程 A 获取 CPU 时间片并执行

3.1 CPU 时间片由谁分配？

  • 操作系统内核负责调度。内核根据调度算法（如 CFS）决定下一个运行的线程，并分配时间片。
  • JVM 本身不参与调度，它只是将 Java 线程映射到内核线程，然后由操作系统决定哪个线程获得 CPU。
  • 当线程 A 获得时间片时，操作系统会将 CPU 控制权交给它，恢复其上下文，JVM 开始执行字节码。

3.2 执行到 synchronized(lock)

  • JMM 视角：线程 A 的工作内存中需要包含 lock 对象的引用（可能还有其它共享变量）。lock 对象本身在主内存（堆）中，但工作内存中会存有它的副本（如锁状态等）。
  • 锁的获取：
    • JVM 执行 monitorenter 指令，尝试获取 lock 对象的监视器锁。
    • 若锁未被占用，JVM 将当前线程设为锁的持有者，并将锁计数器设为 1。
    • 若锁已被线程 B 持有，则线程 A 进入阻塞状态，JVM 将其挂起，操作系统会调度其他线程。

假设此时锁空闲，线程 A 成功进入同步块。

3.3 执行 new Teacher()

  • 对象创建（详细步骤之前讲过）：
    1. 分配内存：在堆上分配内存。JVM 优先使用TLAB（线程本地分配缓冲区），这是线程私有的，无需同步。如果 TLAB 不够，再通过 CAS 在堆上分配。
    2. 设置对象头：包含指向方法区中 Teacher 类元数据的指针、GC 分代年龄、哈希码等。
    3. 执行构造函数：初始化字段。
  • 局部变量：引用 t 存储在虚拟机栈的局部变量表中，指向堆中的 Teacher 对象。
