一 判断：是否通过 ZSet 实现？

是的，Redis 的有序集合（Sorted Set，简称 ZSet）是构建实时排行榜的标准方案。它天然支持按分数排序、高效的范围查询和排名计算，非常适合“骑手按配送单量/积分/时长实时排名”的场景。

二 ZSet 为什么能实现排行榜？

排行榜的核心需求是：

  • 实时更新：骑手完成一单，分数（如单量）立即增加。
  • 高效查询：获取某个骑手的排名、获取 Top N 骑手、获取某个分数区间的骑手。
  • 高并发：百万骑手，每秒可能上千次更新和查询。

ZSet 提供了 O(log N) 的插入、更新、删除和排名查询操作（N 为成员数量），且所有数据存储在内存中，能够支撑百万级成员的高频读写。

三 ZSet 的常用命令及在排行榜中的应用

命令 作用 排行榜场景示例
ZADD key score member 添加或更新成员分数 ZADD rider:rank 100 "rider_12345"（骑手完成第100单）
ZINCRBY key increment member 增加成员分数 ZINCRBY rider:rank 1 "rider_12345"（每完成一单加1分）
ZRANK key member 获取成员排名（从低到高） ZRANK rider:rank "rider_12345" → 排名（第0名为第1名）
ZREVRANK key member 获取成员排名（从高到低） 排行榜通常用这个获取骑手的降序排名
ZRANGE key start stop [WITHSCORES] 按分数升序获取指定范围成员 较少用于排行榜头部
ZREVRANGE key start stop [WITHSCORES] 按分数降序获取指定范围成员 ZREVRANGE rider:rank 0 9 WITHSCORES → 获取前10名骑手
