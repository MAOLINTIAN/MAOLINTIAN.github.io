案例 1：COUNT(*) 查询 - 驱动表全表扫描优化

完整 SQL
SELECT COUNT(*)
FROM `store_status_online`
  JOIN `store_dict` ON `store_status_online`.`gid` = `store_dict`.`gid`
  JOIN `store_with_coop` ON `store_with_coop`.`coop_store_no` = `store_status_online`.`coop_store_no`
  JOIN `store_ref` ON `store_ref`.`link_store_no` = `store_status_online`.`link_store_no`
WHERE
  `store_status_online`.`status` = 1
  AND `store_ref`.`status` = 1
  AND `store_ref`.`is_latest_version` = 1;

问题分析：

  • 🔴 驱动表：store_dict 全表扫描 50,650 行
  • 🔴 type：index（索引全扫描，相当于全表扫描）
  • 🟡 filtered：store_status_online 只有 50%（一半数据被 WHERE 过滤）
优化方案
-- 为 store_status_online 创建复合索引
ALTER TABLE store_status_online
ADD INDEX idx_status_id_all (
  status,           -- WHERE 条件
  id,               -- ORDER BY（如果需要）
  link_store_no,    -- JOIN 关联
  gid,              -- JOIN 关联
  coop_store_no     -- JOIN 关联
);

-- 更新统计信息
ANALYZE TABLE store_status_online;

优化效果：

  • ✅ 驱动表改变：store_dict → store_status_online
  • ✅ 扫描行数：50,650 → 1,905（减少 96.2%）
  • ✅ type：index → ref（使用索引定位）
  • ✅ filtered：50% → 100%（完美过滤）
  • ✅ Extra：Using index（覆盖索引，无需回表）

案例 2：分页查询 - filtered 过滤率优化

完整 SQL
SELECT
  `store_status_online`.`link_store_no`,
  `store_ref`.`com_tax_no`,
  `store_dict`.`city_code`,
  `store_ref`.`store_status`
FROM `store_status_online`
  JOIN `store_dict` ON `store_status_online`.`gid` = `store_dict`.`gid`
  JOIN `store_with_coop` ON `store_with_coop`.`coop_store_no` = `store_status_online`.`coop_store_no`
  JOIN `store_ref` ON `store_ref`.`link_store_no` = `store_status_online`.`link_store_no`
WHERE
  `store_status_online`.`status` = 1
  AND `store_ref`.`status` = 1
  AND `store_ref`.`is_latest_version` = 1
ORDER BY `store_status_online`.`id` DESC
LIMIT 200 OFFSET 52000;

问题分析：

  • 🟡 驱动表：store_status_online 使用 PRIMARY 索引（主键顺序扫描）
  • 🔴 filtered：10%（90% 的数据被 WHERE 过滤掉）
  • 🟡 type：index（索引全扫描）
  • ⚠️ 深分页：OFFSET 52000 需要扫描 52,200 行后丢弃前 52,000 行

优化效果：

  • ✅ type：index → ref（使用索引定位）
  • ✅ key：PRIMARY → idx_status_id_all（使用新索引）
  • ✅ rows：3,811 → 1,905（减少 50%）
  • ✅ filtered：10% → 100%（⬆️ 10 倍）
  • ✅ Extra：Using where → Using index（覆盖索引）
  • ⚠️ 深分页问题依然存在（需改代码用游标分页）
