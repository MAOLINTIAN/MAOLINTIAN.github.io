分布式锁是分布式系统中控制共享资源互斥访问的核心技术。Redis因其高性能成为实现分布式锁的热门选择，但一个可靠的分布式锁需要考虑诸多细节。本文将从最基础的实现开始，逐步剖析每个环节可能出现的问题及其解决方案，最终引出Redisson客户端的成熟实现。

一、最简单的实现：SETNX

最初级的分布式锁实现基于Redis的SETNX命令：

SETNX lock_key unique_value

这个命令的含义是：如果lock_key不存在，则设置成功并返回1；否则返回0。这保证了互斥性。

问题1：没有过期时间，可能死锁

如果客户端获取锁后崩溃，锁将永不过期，其他客户端永远无法获取锁。

为了解决这个问题，我们加上EXPIRE命令：

Boolean locked = jedis.setnx("lock", "value");
if (locked) {

   
    jedis.expire("lock", 30); // 设置30秒过期
}

问题2：加锁与设置过期时间非原子操作

如果SETNX成功后，在设置EXPIRE之前程序崩溃，锁依然无法释放。

解决方案：使用SET NX EX原子命令

Redis从2.6.12开始支持SET命令的扩展参数，可以一步完成：

SET lock_key unique_value NX EX 30
  • NX：只在键不存在时设置。
  • EX 30：设置过期时间为30秒。

这个命令保证了加锁和设置过期时间的原子性，解决了死锁问题。

问题3：锁过期但业务未完成

假设业务逻辑需要35秒才能执行完，而锁只有30秒有效期。30秒后锁自动释放，其他客户端可能获取锁，导致并发冲突。
